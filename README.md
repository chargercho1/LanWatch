# LanWatch

Видеть, что происходит с устройствами в сети: с компьютера, с планшета и с телефона.

Компьютер — основа. Он поднимает сервер, раз в 20 секунд обходит домашнюю сеть и знает, кто в
ней есть. Телефон и планшет ставят агента: он сообщает компьютеру **свой заряд, зарядку, модель
и состояние**, а компьютер в ответ присылает им список **всей сети**. Поэтому один и тот же
список виден с любой стороны — на телефоне он не урезан до одной строки «про себя».

Телефон при этом остаётся телефоном: агент работает фоновой службой с уведомлением, и компьютер
видит его заряд, даже когда телефон лежит в кармане.

## Как запустить

```bash
bash build.sh
```

Соберётся три файла:

| Файл | Что это |
|---|---|
| `LanWatch.exe` | запуск программы на компьютере (Windows) |
| `LanWatch.jar` | та же программа, если `LanWatch.exe` не подходит |
| `LanWatchAgent.apk` | агент для телефона и планшета |

Нужны **JDK 17** и **Android SDK** (build-tools, platform 34). Скрипт берёт их из `~/tools/jdk17`
и `~/tools/android-sdk` либо из `JAVA_HOME` / `ANDROID_SDK_ROOT`.

### Компьютер

Запустите `LanWatch.exe`. Окно показывает адрес, на котором сервер слушает, — например
`192.168.0.23:43121`. Это и есть то, что нужно телефону.

Запустить без `.exe` тоже можно, но на масштабированном экране (125% и выше) правая часть окна
обрежется: Windows уменьшает окно процесса, который не объявил себя DPI-осведомлённым, а JVM
объявить это не умеет. Манифест в `LanWatch.exe` — это ровно то, чего не хватает:

```bash
java -jar LanWatch.jar          # без лаунчера: окно может обрезаться
```

### Телефон и планшет

```bash
adb install LanWatchAgent.apk
```

Или скопировать `.apk` на устройство и открыть в файловом менеджере. **Android 5.1 и новее.**

Агент при запуске сам спрашивает сеть: кто в ней компьютер. Если ответ пришёл — подключается сам.
Если сеть блокирует широковещание (бывает на некоторых роутерах), впишите адрес вручную в поле
«адрес компьютера» и нажмите «Сохранить и переподключиться».

Один компьютер — сколько угодно телефонов и планшетов.

## Что видно на каждом экране

| | Компьютер | Телефон и планшет |
|---|---|---|
| своё устройство | — | заряд, зарядка, экономия, экран |
| другие агенты | модель, заряд, зарядка, время связи | то же |
| устройства без агента | адрес, имя, MAC, открытые порты | то же |
| счётчики | сколько всего, сколько агентов, сколько с зарядом ≤ 20% | — |

Оформление одно на обеих сторонах: Material You. На Android 12+ цвета берутся из палитры обоев,
на более старых версиях и на компьютере — своя тональная палитра, тёмная по умолчанию и светлая
в светлой теме.

## Как это работает

```
телефон/планшет  ──hello, update──▶  компьютер (порт 43121)
                   ◀──roster────────     список всех устройств

компьютер ──раз в 20 с──▶ 192.168.0.0/24: проверка доступности + 16 портов
компьютер ◀──LANW?─────── телефон: «где компьютер?»   (UDP 43122, широковещание)
компьютер ──LANW1 192.168.0.23──▶
```

Одно JSON-сообщение в строке. Общий код — [Json.java](shared/app/lanwatch/Json.java),
[Protocol.java](shared/app/lanwatch/Protocol.java), [Device.java](shared/app/lanwatch/Device.java),
[Address.java](shared/app/lanwatch/Address.java) — компилируется и в программу, и в агента,
поэтому обе стороны не могут разойтись в формате.

### Откуда берутся данные

| Поле | Источник |
|---|---|
| заряд, зарядка, экономия, экран | агент на устройстве: системная батарея и питание |
| модель, система, версия Android | агент |
| адрес, MAC | ARP-кеш системы: Java не умеет спрашивать MAC напрямую, но система знает всё, с чем только что общались |
| имя, открытые порты | обратный DNS и подключения к типовым портам |

**Чего LanWatch не делает.** Заряд есть только у тех, кто запустил агента: у чужого устройства
через сеть спросить заряд нельзя, это не публичный протокол. Уровень сигнала и точное местоположение
не показываются — на Android это требует разрешения на геолокацию. Видеонаблюдение, Wake-on-LAN и
управление устройствами — тоже нет.

Если сеть отвечает почти на все адреса (бывает в виртуальных машинах, VPN и песочницах), сканирование
отбрасывается целиком, а внизу окна появляется объяснение. Лучше пустой список, чем 254 выдуманных
устройства.

## Проверки

```bash
java -cp out app.lanwatch.SelfTest           # 103 проверки формата, слияния и сети
java -cp out app.lanwatch.IntegrationTest    # 20 проверок на настоящих сокетах
```

Обе запускаются на каждой сборке. Интеграционная поднимает настоящий сервер, подключается к нему
как телефон и читает ответ обратно — так ломается не только логика, но и сам протокол.

Окно можно отрисовать в файл, не делая скриншот:

```bash
java -jar LanWatch.jar --shot layout.png
```
